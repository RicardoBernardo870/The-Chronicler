## Overview

This file is the **register of every business rule that only a client enforces today**. It is deduplicated across all domains. The domain files (01–11) specify each rule in full. This register answers three questions per rule:

1. Where is the rule specified?
2. Where does it live in the web PWA today?
3. Where does it live after Phase 0: on the shared backend (a BC work package) or in every client?

It exists because The Chronicler (internal code name BookHero, D-03) is moving to several clients on **one** Supabase backend: the web PWA (live, D-05), the native iOS app (next, iOS 26+, D-04) and Android (later). Per D-06, core logic moves server-side **before** the iOS build, so the native clients stay thin.

How to read the register:

- Every row is enforced **only in the web client** (`client`) today. The *Today* column names the web file. A server object is named only where one already exists.
- **Rule IDs CL-01 … CL-90** keep the numbering of the original native replication checklist (groups A–K). **CL-91 …** are rules added from the client-only sections of the domain analyses.
- A row that describes a defect ends with ⚠ and points to [Known defects](#known-defects) or to the domain defect ID. Defects are stated, not normalised into rules.

## Flows

### F1 · Online page save (session end or pencil correction)

**Today (web, client-orchestrated):**

1. Validate: clamp to `[0, total]`; block an unchanged page ([CL-11](#cl-11)).
2. Optimistic state: `lastPageSavedAt[book] = now`, which starts the 6 h recap cooldown and resets the 48 h "away" clock. The library entry and percentage update locally.
3. Upsert `reading_progress {current_page}`. The DB stamps `updated_at`; when `current_page ≥ total_pages` the completion triggers delete captures and quiz. *Persisted:* page and `updated_at`. On failure: roll back local state and show a toast; nothing else runs.
4. Insert `progress_history` with device-clock `recorded_at` and, if a session ran, the pause-shifted `session_start_at`. *Persisted:* history row (+10 XP, a streak day). On failure: swallowed; the page stays saved and the session is lost from stats.
5. If a session was active: clear the session columns (not awaited) and invalidate velocity.
6. Invalidate `library`, `lastSession`, `readingStats`, `readingQuest*`.
7. Emit `lastSessionEnded`, which raises the capture prompt ([CL-46](#cl-46)).
8. If `prevPct < 100 ≤ newPct`: completion dialog; passport generation if no row exists (fire-and-forget); hero rotation on the Dashboard ([CL-19](#cl-19)).
9. Milestone detection → lore generation, fire-and-forget ([CL-20](#cl-20), [CL-59](#cl-59)).

**After Phase 0 (BC-04 / BC-05 / BC-08 / BC-09, every client):**

1. Validate for UX only. Create an idempotency key for this save.
2. Call `save_progress(book, page, note, null, key)`. One transaction on the server clock validates the page, ends any session (`kind = 'session'` or `'update'`), writes `reading_progress` and `progress_history`, stamps `completed_at` at the first crossing, and fires the L-1 lifecycle effects (passport, Insight jobs, DNA eligibility, achievements, deferred capture purge).
3. Apply the response:
   - replace local progress with `progress`;
   - show the completion dialog when `completion.completedNow`;
   - show the capture prompt only when `effects.captureAllowed`;
   - show the Insight banner while `effects.insightMilestonesQueued` is non-empty;
   - celebrate `effects.achievementsEarned`;
   - rotate the hero; invalidate per [CL-86](#cl-86).
4. **Failure paths.**
   - Typed `P0001` error (`page_out_of_range`, `page_unchanged`, `no_pages_read`, `book_dnf`, `book_not_found`): show copy; nothing was written.
   - Network error after send: retry with the **same** key. `"replayed": true` means the first attempt was applied.
   - No connection: go to F3.

### F2 · Session state machine (per book)

| State | Event | Today (web write, device clock) | After BC-04 | Guards |
|---|---|---|---|---|
| Idle | Start (after warm-up confirm, [CL-98](#cl-98)) | upsert `current_page` (cached), `session_start_at = now`, `session_paused_at = null` | `start_session` (never touches `current_page`) | not complete, not DNF, online ([CL-15](#cl-15)) |
| Running | Pause | update `session_paused_at = now` | `pause_session` | session exists |
| Paused | Resume | `session_start_at += now − paused_at`; `paused_at = null` | `resume_session` | session exists |
| Running / Paused | Save page | F1 (paused tail excluded) | `save_progress` → Idle | page rules ([CL-11](#cl-11)) |
| Running / Paused | Cancel | clear both columns; no history | `cancel_session` → Idle | — |
| Running / Paused | Shelve (DNF) | DNF upsert clears the session; no history | `mark_dnf` → Idle (OP-04.4) | not complete |
| Running / Paused | Completing write (any path) | session survives ("zombie", [CL-24](#cl-24)) | the L-1 trigger clears the session | — |
| Running (> 12 h) | Foreground | timer keeps running | `sessionStale: true` → ask to end or cancel (OP-04.7) | — |

The timer is always rendered from timestamps ([CL-97](#cl-97)). Native clients refetch `session_paused_at` on foreground, so a session started or paused on another device is reflected.

### F3 · Offline page save and replay

**Today:**

1. `navigator.onLine === false` → enqueue `{type: 'progress_update', payload: {bookId, currentPage, updatedAt}, retries: 0}` in IndexedDB `chronicler-offline/progress_queue` (not user-scoped).
2. Optimistic: local page, library status, `lastPageSavedAt` (starts the recap cooldown) and the completion prompt if the page reaches the end. No history, capture prompt, Insight or passport.
3. Drain on the `online` event, on the service worker's `FLUSH_PROGRESS_QUEUE` message (Background Sync tag `progress-sync`), or during a progress fetch. Records replay FIFO as `reading_progress` upserts by **whoever is signed in**. `updated_at`, and therefore the quest year, is stamped at drain time. A failing record (e.g. FK on a deleted book) stays forever.

**Target (D-08, BC-04), every client:**

1. Enqueue `{userId, bookId, page, note?, occurredAt (device), idempotencyKey}` in a **per-user** store.
2. Apply optimistic local state. Show the completion prompt locally if the page reaches the end ([CL-Q05](#cl-q05)).
3. Drain only the current user's records, serialised (one drain at a time), through `save_progress(…, p_client_occurred_at = occurredAt, p_idempotency_key)`.
4. Handle the outcomes:
   - `stale: true` — history written at the original time, page not moved: refresh the book;
   - `replayed: true` — already applied: drop;
   - `book_not_found` — drop;
   - `invalid_occurred_at` (older than 30 days): dead-letter and tell the reader;
   - `book_dnf` / `page_out_of_range`: dead-letter.
5. On a user change, records belonging to another user are never replayed ([CL-02](#cl-02), [PLT-Q01](08-platform-auth-account.md#open-decisions)).

### F4 · Completion: who fires what

Today six completion paths fire six different subsets of effects; the full matrix is [XD-14](11-cross-domain.md#xd-14--six-completion-paths-fire-six-different-effect-subsets).

| Path | Client effects today | After BC-04 / BC-05 |
|---|---|---|
| Online save (Dashboard, Book Detail) | prompt, passport, ≤ 90 % Insight, hero rotation (Dashboard only); DB purge | Server: `completed_at`, session end, passport + summary job (when reading history exists), Insight backlog, achievements, DNA eligibility, deferred purge. Client: prompt, hero rotation, local purge ([CL-50](#cl-50)). |
| Offline save → drain | prompt at save time only | Same server effects at replay, dated by the occurred time. |
| Add as "Already finished" | none ("View Journey" dead end) | `set_initial_status` writes a baseline; `completed_at` stamped; no passport, no AI job (OP-05.2). |
| CSV import "read" | none | `import_library` sets `completed_at = dateRead`; no AI effects. |
| `total_pages` lowered to ≤ `current_page` | none | L-1 `books` trigger runs the completion pipeline (OP-05.4). |

### F5 · Recap generation

**Today (web):**

1. Lock check on the client ([CL-51](#cl-51)).
2. Mode selection ([CL-52](#cl-52)). Inferred mode needs the confirm dialog.
3. `generate-recap` streams text.
4. The client parses the text, inserts the `recaps` row (`pending`), then requests the image ([CL-53](#cl-53)).
5. The client polls `image_status` every 2 s ([CL-56](#cl-56)).
6. Dismiss mid-stream discards the result on the Dashboard only ([CL-54](#cl-54)).

**After BC-07 (every client):**

1. Read `get_recap_eligibility(book)` and render the lock labels from it.
2. When eligible, send v2 `{apiVersion: 2, bookId, requestId, kind: 'recap'}`.
3. Read NDJSON lines: `accepted` (with the server-chosen `mode`) → `progress` (`stage`) → `recap` (the persisted row) or `error`.
4. The server enqueues the image job.
5. The client polls the row with a cap, refreshes on foreground, or uses Realtime (BC-14). A disconnect after `accepted` still yields one saved recap, which `get_recap_request(requestId)` returns.
6. Error outcomes:
   - `409 recap_locked` → show the lock;
   - `409 recap_in_progress` → attach to the running request;
   - 402 / 429 → entitlement copy (BC-12).

### F6 · User change (sign-out or account switch): required native sequence

1. Stop timers and cancel per-user in-flight tasks (AI calls, enrichment, extraction). Bind any task that must finish to the user who started it.
2. Handle unsynced offline saves for this user: flush if online, else warn before discarding ([PLT-Q01](08-platform-auth-account.md#open-decisions)).
3. Remove the device's push token when BC-14 `device_tokens` exists.
4. Sign out: complete the local sign-out even if the network call fails. Scope per [PLT-Q01](08-platform-auth-account.md#open-decisions) / OP-11.2.
5. Wipe every per-user artefact:
   - stores and caches;
   - the offline queue;
   - widget / App Group data and Spotlight entries;
   - Live Activities and scheduled local notifications;
   - module singletons: achievements ledger, quiz cache, Codex results, gallery, community identity, the WotD pick.
6. Show the sign-in screen.

Device preferences ([CL-87](#cl-87)) survive. The PWA today performs only step 4 and clears SWR metadata ([CL-D01](#cl-d01)).

### F7 · Book delete: required native sequence

1. Confirm with the [LIB-87](01-library.md#lib-87--delete-confirmation) copy. Safeguards (active session, unsynced saves, AI job in flight, owned circle): [LIB-Q12](01-library.md#open-decisions).
2. Call one server delete. The FK cascade removes progress, history, recaps, lexicon, lore, passport, captures, quiz, Up Next row, vocabulary ledger and circle rows. `reading_quest_events.book_id` is set to NULL.
3. On success, purge local artefacts for the book:
   - library entry, progress, session state;
   - captures, quiz, resumes;
   - recaps, gallery items, lore, passport;
   - lexicon entries, the WotD pointer if it pointed into the book, Codex results;
   - queued saves.
4. Cancel the book's tasks, end its Live Activity and reload widgets.
5. Invalidate stats, records, last session, velocity, quest and breakdown ([CL-86](#cl-86)).
6. Server side after Phase 0: queued jobs cascade, running jobs re-check existence before writing (BC-05), and recap images are removed by the cleanup queue (BC-13).

**Transition rules for every client:**

- **Before a package ships**, a client implementing a row marked `server — …` copies today's rule exactly, **minus its listed defects**. It must not "improve" semantics on its own; for example, writing history on offline replay would change everyone's stats. The fix is the package.
- **When a package ships**, the matching catalog rules change from "client-only" to "server-enforced" in the same PR (plan principle P5). Here the row's *Today* column changes, and its ID stays.
- **Phase-0 exceptions** stay client-side by decision: session warm-up ([CL-47](#cl-47), [CL-48](#cl-48)), vocabulary auto-extraction ([CL-69](#cl-69)), resume and quiz persistence. They are the only AI-adjacent logic a native client still owns.

## Caching & offline

**Cache model.** The PWA's SWR primitive stores freshness metadata only; data lives in Pinia stores and module singletons ([PLT-24](08-platform-auth-account.md#plt-24--the-cache-stores-freshness-metadata-only)). Native clients use a per-user repository with freshness timestamps and the same TTLs ([CL-85](#cl-85)). They refresh stale entries on foreground and apply the invalidation matrix with its gaps closed ([CL-86](#cl-86)).

|---|---|---|---|
| `books:{uid}`, `library:{uid}`, `upNext:{uid}` | 60 s | yes | one library store keyed by book id; BC-14 delta later |
| `progress:{uid}`, `lastSession:{uid}` | 30 s | yes | progress derived from the library RPC when present |
| `lexicon:{uid}:{bookId}`, `lexicon:{uid}:all` | 60 s | yes | today's set from BC-10 when adopted |
| `recaps:{uid}:{bookId}`, `bookPassport:{uid}:{bookId}` | 60 s | yes | recap rows arrive in the BC-07 response |
| `readingQuest:{uid}:{year}` (prefix-invalidated) | 60 s | yes | pass `p_timezone` |
| `lore:{uid}:{bookId}`, `lore:{uid}:all` | 120 s | yes | the all-books list must drop deleted books |
| `readingStats:{uid}`, `libraryBreakdown:{uid}`, `readingRecords:{uid}` | 120 s | yes | records are never invalidated today |
| `velocity:{uid}` | 365 days | **no** | cache per book ([CL-110](#cl-110)) |
| Calendar months, monthly years | app session | no | refetch the current month and year on foreground |
| Captures, `quizByBook`, achievements ledger, gallery | app session | no | per user; purge on completion and delete |

**Offline behaviour.**

- **Works offline in the PWA:** reading cached screens and saving a page (queued, [CL-27](#cl-27)).
- **Needs the network:** session start, pause, resume and cancel; DNF; library mutations ([CL-103](#cl-103)); capture and OCR ([CL-104](#cl-104)); every AI call; search; import; Codex search; profile edit.
- **Native target:**
  - page saves, including session end, queue per user and replay through `save_progress`;
  - everything else stays online-only with clear copy until a domain decision says otherwise ([CL-Q04](#cl-q04)).

## Notes for native clients

### Platform-agnostic (iOS now, Android later)

- **Thin client (D-06).**
  - Never re-implement a row whose target is `server — … (pre-iOS)`: call the RPC and render its result.
  - The iOS build starts after Waves 1–3. Until Wave 4 lands, implement the interim rules of BC-11 … BC-15 rows exactly as the PWA does, minus their defects.
- **Direct table writes after Phase 0** are limited to client-owned data:
  - `books` (add, edit, delete);
  - `up_next_order`;
  - `lexicon_entries` (manual add);
  - `page_captures` (+ `resume`), `book_quizzes`, `vocabulary_extractions`;
  - `reading_goals`;
  - avatar objects in Storage.

  Everything else goes through RPCs or edge functions. Profile changes use `upsert_my_community_profile` with partial updates (BC-11).
- **Identity binding.** Every async task records the user id that started it. Its result is dropped if the signed-in user changed. A user change runs the full wipe (F6).
- **Clocks.** After BC-04, online writes send no timestamps; the server clock decides. Only offline replays send `occurredAt` (F3).
- **Percentages and status.** Derive them at use time from `(current_page, total_pages)`, capped at 100, using the server's precedence ([CL-05](#cl-05), [CL-06](#cl-06)). Never persist a percentage.
- **Dates and zones.**
  - Call `set_my_time_zone` at launch and on a system zone change.
  - Pass `p_timezone` to every stats RPC.
  - Treat `YYYY-MM-DD` fields as floating dates ([CL-07](#cl-07), [CL-08](#cl-08)).
- **Errors.** Switch on `P0001` message codes (`book_complete`, `page_unchanged`, `recap_locked`, …) and on edge-function `error` codes. Never show raw server text.
- **Android (later).**
  - WorkManager drains the per-user queue.
  - ML Kit handles barcode and on-device OCR fallback decisions.
  - Same RPC and edge contracts; the same golden fixtures ([CL-Q03](#cl-q03)).

### iOS-specific (iOS 26+, iPhone first — D-04)

- **Glass.** Native Liquid Glass (`.glassEffect` / `GlassEffectContainer`) is the only glass implementation. There is no pre-iOS-26 fallback branch. Honour Reduce Transparency and Increase Contrast.
- **OCR (D-15).** Apple Vision text recognition runs on-device first, with `ocr-page` as the fallback on low confidence. The 0.90 / 0.70 thresholds are Gemini-calibrated and must be recalibrated for Vision ([CAP-Q07](04-capture-resume-quiz.md#open-decisions)). The capture page is still the progress page ([CL-42](#cl-42)).
- **Offline queue.** A per-user persistent store (e.g. SwiftData), drained when `scenePhase` becomes active and an `NWPathMonitor` path is satisfied. `BGAppRefreshTask` is only a bonus.
- **Session surfaces.** The timer uses `Text(timerInterval:pauseTime:)` from server timestamps. Refetch `session_paused_at` on foreground. Live Activities and widgets reload after every save, and end or reload on book delete and user change. Their v1 scope is [SES-Q19](02-reading-sessions.md#open-decisions).
- **Focus mode.** Disable the idle timer while it is visible. Dim through the window scene's screen. Schedule a local notification for the goal end while locked.
- **Auth (D-11, D-10).**
  - Sign in with Apple through `signInWithIdToken`; email and password; password reset.
  - Magic and reset links arrive as universal links (PKCE).
  - "Link Apple ID" in settings.
  - "Delete account" with re-authentication, calling `delete-account`.
- **Profile v1 (D-13).** Username, display name and avatar only. No bio, privacy settings or public toggle. The follow graph, discovery and circles stay dormant.
- **Background work.** Wrap client-owned writes that must finish (capture save, resume / quiz persistence, vocabulary ledger) in a background task. Server-owned AI work (recaps, Insights, passport, DNA) finishes on the server regardless (BC-05 / BC-07 / BC-08).
- **Networking.** Request timeout ≥ 10 s. One refresh-and-retry on 401. Treat SQLSTATE `57014` (statement timeout) as retryable once.
