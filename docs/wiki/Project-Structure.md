# Project Structure

Last updated: 2026-10-18

One repository holds the Vue 3 PWA, the Supabase edge functions and migrations, and the documentation. The repo, package (`bookhero`), Supabase project and code identifiers use the internal code name **BookHero**; the product is **The Chronicler** (D-03).

---

## Top-level layout

```text
.
├── docs/                    Documentation (see "Documentation map" below)
├── public/                  Static assets: manifest.webmanifest, icons, favicons, apple-touch icon
├── scripts/                 Empty
├── specs/                   Historical Spec Kit artifacts, 001–034 (reference only, D-02)
├── src/                     Vue application source (177 files)
├── supabase/
│   ├── functions/           Deno edge functions + shared import map (deno.json)
│   ├── migrations/          SQL migrations — drifted from live (BC-03)
│   └── reference/           Read-only live schema snapshot (D-16)
├── tests/unit/              Vitest unit tests (26 spec files)
├── .claude/, .specify/      Agent settings; legacy Spec Kit skills and templates (not part of the workflow, D-02)
├── CLAUDE.md, AGENTS.md     Agent context files (auto-generated by Spec Kit; partly stale)
├── index.html               App HTML shell (no manifest link — PLT-D34)
├── package.json             Scripts and dependencies (pnpm)
├── pnpm-lock.yaml
├── tsconfig*.json           TypeScript 6 project references
├── vite.config.ts           Vite + VitePWA (injectManifest)
├── vitest.config.ts         Test configuration
└── vercel.json              Cache headers for Vercel
```

`dist/` (build output) and `.env.local` are ignored. `package.json.tmp` is a tracked stray copy and can be deleted.

## Conventions

- **Package manager: pnpm** (`pnpm-lock.yaml`). Use `pnpm add`; `npm install` fails in this repo.
- Vue components use the Composition API with `<script setup>` and TypeScript strict.
- **Arrow functions only** — no `function` declarations. Known drift: `useOfflineSync.ts`, `stores/recaps.ts`, `App.vue` (`handleSwMessage`), `services/recapService.ts` (`streamRecap`) (PLT-D42).
- Database rows are `snake_case`; app domain types are `camelCase`; mappers live in `src/types/index.ts`.
- Pinia stores own persistence and SWR keys (built with `cacheKeys` in `useCache.ts`); pages/components own UI workflow state.
- Shared state that must survive component unmounts is a **module singleton** composable (`useActiveBook`, `useBookSearch`, `useGlassToast`, …). Singletons are not reset on sign-out (PLT-D12).
- Pure rules go in `src/utils/` so they can be unit-tested.
- Unit tests live in `tests/unit/*.spec.ts` ([Testing](Testing.md)).
- User-facing name is "The Chronicler"; identifiers and storage keys keep `bookhero` (D-03).
- New work follows [Development Workflow](Development-Workflow.md) (Claude Code; no Spec Kit).
