# Implementation Plan: Library Page Overhaul

**Branch**: `019-library-page-overhaul` | **Date**: 2026-05-01 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/019-library-page-overhaul/spec.md`

## Summary

Fix two data-correctness bugs (genre not returned by the library RPC; ISBN silently discarded on book edit), then layer five UX improvements on top of an accurate book card: section headers with counts + collapsible Archives, "Page X of Y" + days-remaining estimate for in-progress books, swipe-left Edit/Delete actions, and optimistic drag-and-drop reordering for The Queue. All changes are contained within the Vue/Pinia/Supabase frontend stack; no new npm packages are introduced.

## Technical Context

**Language/Version**: TypeScript 6 (strict) + Vue 3.5 (Composition API, `<script setup>`)  
**Primary Dependencies**: PrimeVue 4, Pinia 3, Supabase JS v2, Vue Router 4, VueUse  
**Storage**: Supabase PostgreSQL (existing schema — one SQL amendment to `get_library_with_progress` RPC)  
**Testing**: Manual smoke tests per quickstart.md  
**Target Platform**: PWA (mobile-first, iOS + Android + desktop)  
**Project Type**: Web application (PWA)  
**Performance Goals**: Drag-and-drop position settles in < 100 ms (SC-003); edit + genre reflect on card within 1 s (SC-001)  
**Constraints**: Zero new npm packages; must not regress offline queue or SWR caching behaviour  
**Scale/Scope**: Single-user library of 1–200 books; no new DB tables required
