# Implementation Plan: Recap Image Generation

**Branch**: `021-recap-image-generation` (currently authored on `master` — feature branch not yet cut)
**Date**: 2026-05-03
**Spec**: [spec.md](./spec.md)

## Summary

Extend the existing `generate-recap` Edge Function to produce a single 1:1 square image alongside the three existing text fields (`memory_jogger`, `thematic_bridge`, `concept_watchlist`). The image is generated by `gemini-2.5-flash-image` from a refined prompt that consumes **only** the `memory_jogger` plus the current book's metadata — never the other text fields, never hardcoded book examples. Image bytes are persisted to Supabase Storage; the recap row stores a reference plus a status enum. Failures degrade gracefully: one silent transient retry, one safety-rejection retry with a softer prompt, then the recap settles into a no-image state with no manual retry exposed in the UI.

The PWA renders the image as a decorative element inside the existing recap card. No alt text is generated — the image is treated as decorative; assistive technologies skip it.

## Technical Context

**Language/Version**: TypeScript 6 (strict) on Vue 3.5 (`<script setup>`); Deno (Supabase Edge Functions) for backend
**Primary Dependencies**: PrimeVue 4 (Image, Skeleton), Pinia 3, Supabase JS v2, Vue Router 4, Google Generative Language API (`gemini-2.5-flash-image` model)
**Storage**: Supabase PostgreSQL — `recaps` table extended with three nullable columns (`image_path text`, `image_status text`, `image_generated_at timestamptz`); Supabase Storage — new private bucket `recap-images` keyed `{user_id}/{recap_id}.png`
**Testing**: Vitest for client, Deno test for Edge Functions; manual E2E via the staging Supabase project
**Target Platform**: PWA (modern evergreen browsers), iOS 17+ Safari, Android Chrome
**Project Type**: Web (Vue PWA frontend + Supabase Edge Function backend)
**Performance Goals**: Text recap time-to-first-token unaffected (no regression). End-to-end image visible at p90 ≤ 2× the time to text-recap visible (per SC-008). Image binary ≤ 500KB after compression.
**Constraints**:
- Spoiler-safe (Constitution I): image cannot depict content beyond the user's progress.
- Three-tiered text output preserved (Constitution I): existing fields untouched.
- Latency budget: image generation does not block text streaming (FR-022).
- No hardcoded book/author/world names in the prompt-refinement template (FR-006, SC-010).
- Image must remain decorative — no alt text generation or storage (per Clarification 2).
**Scale/Scope**: Per-recap image (1 image per generated recap). Expected volume: low thousands of images per month at current usage; tens of thousands at full launch. Bucket sizing: ~500KB × 50K images = ~25GB at scale (well within Supabase Storage limits).

**Structure Decision**: Web (Option 2 — frontend + backend). The feature is split across the existing Vue PWA and the existing `generate-recap` Edge Function. No new top-level directories are introduced; the work is additive within established locations:

- **Image-prompt refinement** lives next to existing prompt builders in `supabase/functions/generate-recap/prompts/`. Pure function, no I/O, easy to unit-test in isolation.
- **Image generation orchestration** lives next to existing handlers in `supabase/functions/generate-recap/handlers/`. Reuses the same Supabase admin client, the same auth check, the same logging.
- **UI rendering** lives in `src/components/recap/RecapImagePanel.vue` — single-responsibility (≤ 250 lines target), uses PrimeVue `Image` + `Skeleton`. Mounted inside the existing `RecapStream.vue` so the image visually anchors with the streaming text.
- **Storage** uses a new Supabase Storage bucket `recap-images` (private, RLS-tied to `auth.uid()`).
- **Schema change** is one small additive migration on the existing `recaps` table — no breaking changes, no rename.

The modularity requirement of FR-024 is satisfied by isolating `imagePromptRefiner.ts` (pure) and `handlers/image.ts` (orchestration) so a future feature like passport images or lore images can call them without code duplication.
